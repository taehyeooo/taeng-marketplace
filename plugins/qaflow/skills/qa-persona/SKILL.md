# 페르소나 QA (qaflow)

페르소나 하나 = **누구인지 + 기기 상태 + 데이터 상태 + 하려는 일**. 많이 만들기보다 축(경험·데이터 양·기기·맥락·하려는 일)의 조합이 빠짐없게 고른다.
기본 세트(core 5~7명)는 배포 전마다, 확장 세트(extended)는 큰 기능·출시 전에.

## 순서
1. `qa-env quota`로 외부 API 사용량 확인(공유처럼 AI를 부르는 시나리오가 있으면 남은 양을 알림).
2. `bash "${CLAUDE_PLUGIN_ROOT}/scripts/persona.sh" run core` (또는 extended / all / 페르소나 id) — 페르소나마다 기기 설정 → 데이터 픽스처 → 로그인 상태 → 시나리오 → 캡처 → 데이터 정리가 자동으로 돈다.
3. **평가(직접)**: 실행 기록의 페르소나마다 시나리오 캡처 묶음을 읽고, 그 사람의 `who`·`goal` 입장에서 `judge` 항목을 하나씩 본다.
   찾은 것은 JSON 배열로 — `[{"title","where","severity":"높음|중간|낮음","kind":"이번 변경|원래 있던 문제","suggest"}]` — `persona.sh findings <기록> <id> <파일>`.
   없으면 빈 배열로 기록한다(성과 집계에 쓰임).
4. `persona.sh report <기록>` → HTML 리포트(한눈에 표 · 찾은 것 전체 · 페르소나별 캡처 · 누적 성과). 경로와 목록 페이지(`~/.config/flow-reports/index.html`)를 사용자에게 알린다.
5. `persona.sh stats`로 여러 번 돌려도 아무것도 못 찾는 페르소나는 빼거나 합치자고 제안하고, 실제 사용자 불편·버그가 들어오면 그 상황을 새 페르소나로 추가한다.

## 지킬 것
- 결과는 **가상 사용자 관점**이다 — 실제 사용자 조사를 대신한다고 말하지 않는다.
- 데이터 픽스처는 AI 호출 없이(기존 결과 복사·API) 만든다. 테스트 계정에만.
- 심각도는 "그 사람이 하려는 일을 못 하게 되면 높음, 돌아가지만 헷갈리면 중간, 보기만 어색하면 낮음".
