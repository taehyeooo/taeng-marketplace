# 한국어 화면 문구

화면에 보이는 글은 사용자가 읽는 유일한 설명이다. 아래 규칙으로 쓰고, 고칠 때는 `이전 → 이후`로 보여 준다.

## 규칙
1. **짧고 쉬운 말.** 한 문장에 한 가지. 한자어·외래어보다 쉬운 우리말(`진행하시겠습니까` → `할까요`, `입력값` → `적은 내용`).
2. **해요체로 통일.** 한 화면·한 서비스 안에서 `~합니다`·`~하세요`·`~해요`를 섞지 않는다. 기본은 해요체(`저장했어요`, `다시 해 주세요`). 과한 높임(`~하시겠어요?` 반복)도 줄인다.
3. **버튼은 동사.** 누르면 일어나는 일을 쓴다(`확인` → `저장하기`/`삭제`). 대화상자의 두 버튼은 결과가 다른 동사로(`삭제` / `취소`), `예`/`아니오`는 쓰지 않는다.
4. **오류는 "무엇이 왜 + 어떻게".** 사용자 탓으로 쓰지 않고, 코드·영문 원문을 그대로 보이지 않는다.
5. **빈 상태는 "무엇이 없고 + 무엇을 하면 되나".** 버튼으로 다음 행동을 준다.
6. **숫자·단위.** 금액 `4,900원`(천 단위 쉼표, 숫자와 단위 붙여 씀), 날짜 `2026년 10월 15일` 또는 `10월 15일 (목)`, 시각 `오후 3:05`, 기간 `3일 남음`. 코드에서는 `Intl.NumberFormat('ko-KR')`·`Intl.DateTimeFormat('ko-KR', { timeZone: 'Asia/Seoul' })`로 만든다 — 시간대를 빼면 실행 환경 시간대를 따라 서버 렌더(CI·배포 서버는 대개 UTC)와 브라우저 글자가 달라진다(`오후 3:05` → `오전 6:05`).
7. **전문 용어 빼기.** `세션 만료`, `토큰`, `서버 오류 500`, `null` 같은 말을 사용자에게 보이지 않는다.
8. **같은 것은 같은 이름.** 한 서비스에서 `이용권`·`구독`·`멤버십`을 섞지 않는다 — 처음 정한 이름을 끝까지.
9. **줄바꿈.** 문구가 두 줄을 넘으면 줄인다. 웹은 `word-break: keep-all`(`intaeng:design-review` 8번)로 단어 중간에서 끊기지 않게.

## 이전 → 이후
| 자리 | 이전 | 이후 |
|---|---|---|
| 버튼 | 확인 | 저장하기 |
| 대화상자 | 정말 삭제하시겠습니까? [예] [아니오] | 이 메모를 지울까요? 지우면 되돌릴 수 없어요. [지우기] [취소] |
| 오류 | 오류가 발생했습니다. (500) | 저장하지 못했어요. 인터넷 연결을 확인하고 다시 해 주세요. |
| 오류(입력) | 유효하지 않은 이메일 형식입니다 | 이메일 주소에 @가 빠졌어요. |
| 오류(로그인) | 세션이 만료되었습니다 | 오래 쉬어서 로그아웃됐어요. 다시 로그인해 주세요. |
| 빈 상태 | 데이터가 없습니다 | 아직 주문이 없어요. 상품을 둘러볼까요? [상품 보기] |
| 토스트 | 저장이 완료되었습니다. | 저장했어요. |
| 안내 | 결제 진행 중 페이지를 이탈하지 마십시오 | 결제 중이에요. 이 화면을 닫지 말아 주세요. |
| 숫자 | 4900 원 / 2026-10-15T15:05 | 4,900원 / 10월 15일 오후 3:05 |

## 쓰는 순서
1. 화면에서 글이 나오는 곳을 모두 찾는다(제목·라벨·placeholder·버튼·도움말·오류·빈 상태·토스트·대화상자·`aria-label`).
2. 위 규칙으로 고친 안을 `파일:줄 — 이전 → 이후` 목록으로 보여 준다.
3. 사용자가 고르면 코드에 반영한다. 같은 문구가 여러 곳이면 한 곳(상수·사전 파일)에서 가져오게 한다.
