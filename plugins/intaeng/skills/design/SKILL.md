# 디자인

작업을 계획하기 전에 이 스킬을 읽는다. Claude Code와 Codex가 같은 지침을 사용한다. 참고 도구가 사용자 조사나 사용성 검증을 자동으로 수행한다고 가정하지 않는다.

## 진행 순서

| 단계 | 하는 일 | 남길 것 |
|---|---|---|
| 1. 사용자 흐름 확인 | 대상 사용자·목표·핵심 작업·사용 환경을 확인한다. 사용자 목표 → 진입 화면 → 주요 행동 → 결과 확인과 막히는 지점을 정리한다. 아래 UX 체크리스트로 상태와 복구 경로를 검토한다 | 흐름 한 장, 미확인 내용은 가정 |
| 2. 도구 고르기 | 빠른 선택표와 필요한 도구 참고 파일을 읽고 스택에 맞게 고른다. 전체 방향은 하나를 중심으로, 나머지는 구체적인 보완 역할로 쓴다. 그 기기에 실제로 설치된 도구를 확인한다 | 도구·이유·적용 범위·설치 확인 |
| 3. 시안 3개 | 서로 다른 방향 3개. 각 시안에 콘셉트 한 줄, 바뀌는 화면 전/후 목업(밝은·어두운), 움직임, 바뀌는 디자인 값, 난이도·위험과 추천 순위를 담는다. 사용자가 원하면 Claude와 Codex가 서로 결과를 보지 않고 각각 만든다 | 목업 파일·설명, 한 화면에서 볼 비교 페이지 |
| 4. 사용자 선택 | 시안 고르기는 항상 사용자 몫이다. 비교와 추천만 하고 답을 기다린다. 섞어도 된다 | 고른 것과 사용자 말 그대로 |
| 5. 세부 | 선택한 방향을 나머지 화면·로딩·오류·빈 화면·완료·다크·큰 글자·동작 줄이기까지 구체화한다. 필요하면 다시 고르게 한다 | 사용자에게 확인받은 세부 시안 |
| 6. 적용 | 실제 코드에 반영한다. 테스트 먼저, 기존 디자인 규칙(토큰) 안에서 구현한다 | PR, 전/후 캡처 |
| 7. 검수 | 반대쪽 모델로 시각·접근성·흐름·회귀를 교차 검수한다. 모바일·가독성·키보드·포커스·주요 버튼·오류 복구·동작 줄이기를 확인한다 | 지적·수정 기록, 실행한 검사와 증거 |
| 8. 보고 | 아래 보고 형식으로 설계 제안, 구현 확인, 실제 사용자 테스트 결과를 구분한다 | 결과와 남은 가정·검증 필요 항목 |

단계를 건너뛰지 않는다. 사용자가 범위를 줄이면(예: "시안 없이 바로 고쳐", "문구만 검토해") 그 지시를 따르고 건너뛴 단계를 보고한다. "맡길게"만으로 시안을 대신 선택하지 않는다. 사용자 선택 전에는 실제 앱 코드를 바꾸지 않고 목업을 별도 파일로 만든다. 다른 모델이나 작업자를 쓸 권한·환경이 없으면 직접 검수하고 교차 검수는 미실시로 명시한다. 교차 검수와 독립 시안 제작을 했다고 꾸미지 않는다.

## 도구 선택과 설치

- 기존 디자인 시스템, 이미 합의한 흐름, 사용자 지시가 우선이다. 지식베이스와 프로젝트 디자인 문서의 결정을 먼저 읽고, 도구 때문에 전체 화면이나 서비스 정책을 임의로 바꾸지 않는다. 핵심 정책이 불명확하면 필요한 질문을 한다.
- 메뉴 구조·정보 우선순위·입력 항목·버튼 문구와 상태·복구를 먼저 정한다. UI는 색·글자·간격·배치이고 UX는 목표 달성 흐름·안내·오류 복구·결과 확인이다.
- 고정된 기기별 설치 표를 믿지 않는다. 작업할 기기의 사용 가능한 스킬·플러그인·명령과 실제 설치 상태를 확인한다. 다른 기기에서 쓸 수 있다는 보고를 현재 기기의 설치 증거로 삼지 않는다.
- 필요한 도구가 없으면 설치할 도구·기기·용도·내용을 제시하고 사용자에게 설치 승인을 받는다. 이미 해당 설치를 승인했다면 다시 묻지 않는다. 승인 전에는 설치하지 않는다.
- 승인 후 에이전트가 설치한다. 먼저 공식 README·설치 안내에서 무료인지, 지원 환경과 설치 내용(외부 코드의 설치 스크립트·실행 명령 포함)을 확인한다. 유료면 설치하지 않고 다시 묻는다. 비용 드는 폰트·에셋·서비스는 사용하지 않는다. 목록 전체를 일괄 설치하거나 설치 명령을 추측하지 않는다.
- 설치 후 무엇을 어느 기기에 어떻게 설치했는지와 확인 결과를 보고한다. 프로젝트가 설치 기록을 관리한다면 확인 날짜와 함께 갱신한다.
- 서비스별 디자인 결정(색의 의미, 피할 표현 등)은 그 프로젝트의 디자인 문서에 남긴다. 별도 UX 문서가 없다면 작업 계획에 핵심 흐름부터 적는다. 이 일반 지침을 각 서비스 레포에 통째로 복사하지 않는다.
- 쓰지 않은 도구를 썼다고, 읽지 않은 문서를 읽었다고 보고하지 않는다. 필요한 문서를 찾지 못하면 알린다.

## UX 검토 체크리스트

- **사용자 목표:** 누구의 어떤 문제를 해결하는 화면인가?
- **정보 구조:** 사용자가 필요한 메뉴와 정보를 쉽게 찾을 수 있는가?
- **작업 흐름:** 목적을 달성하기 위한 단계가 불필요하게 많지 않은가? 뒤로 가기와 취소가 가능한가?
- **입력과 안내:** 필요한 항목만 입력받는가? 버튼을 누르면 무엇이 일어나는지 알 수 있는가?
- **로딩:** 진행 중임을 알 수 있는가? 중복 제출을 방지하는가?
- **빈 화면:** 데이터가 없을 때 이유와 다음 행동을 안내하는가?
- **오류:** 무엇이 잘못됐고 어떻게 해결할지 알려 주는가? 가능한 경우 입력 내용이 유지되는가?
- **완료:** 작업이 성공했는지, 이후 무엇을 할 수 있는지 알 수 있는가?
- **접근성과 환경:** 모바일, 키보드, 화면 읽기 도구와 모션 감소 설정을 고려했는가?
- **사용성 확인:** 실제 사용자에게 구체적인 작업을 맡겨 완료 여부, 혼란과 실수를 관찰했는가?

모션은 행동과 상태 변화를 이해하는 데 도움이 될 때 적용한다. 큰 글자와 밝은·어두운 화면에서 가독성·대비·포커스를 확인한다. 문구는 사용자가 아는 말로 버튼의 행동, 오류의 원인과 복구, 완료 후 다음 행동을 드러낸다. 지적은 `파일:줄 또는 화면·상태 — 문제 — 고칠 방법 — 확인 결과`로 남긴다.

## 다른 레포·다른 기기 작업자에게 맡길 때

작업자가 이 스킬을 직접 읽지 못할 수 있다. 맡기는 에이전트가 읽고 다음을 지시문에 옮겨 적는다. 위임을 요청받았거나 허용된 작업에서만 작업자를 사용한다.

- 이번에 맡은 단계, 결과물의 파일 위치와 형식.
- 고른 도구·선택 이유·UI/UX 적용 범위, 그 기기에서 실제로 쓸 수 있는지 확인할 것.
- 쓴 스킬과 그 스킬이 바꾼 결정을 보고할 것.
- 프로젝트별 디자인 결정과 금지 사항, 이번 작업에 필요한 UX 체크리스트 항목.
- 사용자 선택 전 실제 앱 코드 변경 금지, 데이터 바꾸는 동작 금지, 비용 드는 폰트·에셋·서비스 금지.
- 설치가 필요하면 위 승인·무료·설치 내용 확인 규칙을 따르고 기기와 설치 결과를 보고할 것.

## 보고 형식

작업·사용자 목표·UX 흐름, 고른 도구와 이유·적용 범위, 실제 쓴 스킬과 바꾼 결정, 확인한 것과 남은 가정을 짧게 적는다. 건너뛴 단계와 이유, 미실시 교차 검수·미설치 도구도 명시한다.

| 구분 | 기록할 내용 |
|---|---|
| 설계 제안 | 시안·추천 이유·UI/UX 범위·가정, 사용자 선택과 세부 확인, 제안 상태인 내용 |
| 구현 확인 | 고른 시안과 실제 화면의 차이와 이유, 전/후 캡처·파일·PR, 모바일·키보드·주요 버튼·오류 복구 등 실행한 검사와 결과 |
| 실제 사용자 테스트 결과 | 실제 사용자에게 맡긴 구체적인 작업, 완료 여부·막힌 위치·헷갈린 표현·실수·수정 결과. 하지 않았다면 검증 필요 |

도구 검토·자동 테스트 통과를 실제 사용자 테스트로 보고하지 않는다. 목업·프로토타입 완료와 서비스 구현 완료, 영상 미리보기와 최종 영상 렌더링·재생 확인도 구분한다.
