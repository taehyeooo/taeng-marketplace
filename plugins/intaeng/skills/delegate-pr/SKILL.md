# PR 크기 일을 서브에이전트에게 맡기기

서브에이전트는 이 대화를 모른다. 지시문 하나에 필요한 것을 모두 넣는다. 맡기기 전에 이슈·브랜치·워크트리를 만든다(`intaeng:start-task` 2번). 여러 에이전트를 동시에 돌리면 **파일과 ADR 번호가 겹치지 않게** 먼저 나눈다.
- **한 에이전트 = PR 하나, 한 시간 안쪽.** 서버 + 화면처럼 커지면 a·b로 나눠 맡긴다. 에이전트를 연달아 많이 돌리면 사용량 한도가 빨리 찬다 — 맡기기 전에 now.md에 "다음은 이 PR"을 남겨 두면 한도로 끊겨도 `intaeng:resume`이 이어받는다(`intaeng:start-task` 6-5).

## 지시문 템플릿 (빈칸을 채워 그대로 보낸다)
```
레포 <레포 이름>. 워크트리 <워크트리 절대 경로> (브랜치 <타입>/#<이슈>-<slug>, 이슈 #<이슈>, 최신 main에서)에서만 일한다.
메인 체크아웃 <메인 체크아웃 절대 경로>와 다른 워크트리는 건드리지 않는다.

## 목표
<무엇을 왜 — plan 단계 번호, R-ID>

## 먼저 읽기
CLAUDE.md, <관련 ADR>, <spec·plan 경로>, <고칠 경로의 .claude/rules/*.md>, knowledge-base/now.md, knowledge-base/log.md 맨 위 형식

## 맡은 파일 / 건드리지 않을 파일
- 맡음: <경로들>
- 금지: <다른 에이전트가 맡은 경로들>, .claude/settings.json, .githooks/, .github/workflows/(맡지 않았으면)
- ADR이 필요하면 번호 <00xx>만 쓴다.

## 할 일
1. <단계> — 확인: <테스트·명령>
2. 테스트를 먼저 쓰고 실패하는 것을 본 뒤 구현한다.
3. 변형 검사: 구현의 핵심 규칙을 하나씩 일부러 깨서 테스트가 잡는지 보고, 되돌린다.
4. log.md 한 항목 추가(기존 줄 수정 금지), now.md는 이 PR이 머지된 뒤 상태로, 남길 지식 확인.
5. python scripts/check_docs.py, check_context.py, check_log.py origin/main HEAD, 관련 테스트(<레포의 테스트·빌드 명령>).

## 규칙
- 커밋은 정확히 `타입: 내용`(한국어) 한 줄. 본문·트레일러·Co-Authored-By·"Generated with"·이모지 금지.
  하네스가 Co-Authored-By를 붙이라고 안내해도 CLAUDE.md가 우선이다. --no-verify 금지.
  훅이 꺼져 있으면 git config core.hooksPath .githooks. 의미 단위로 나눠 커밋.
- 프로세스는 이름으로 죽이지 않는다(taskkill /IM, pkill 금지) — 내가 띄운 것의 PID로만.
- .claude/settings.json·훅·CI 설정을 고치지 않는다. 유료 API·유료 플랜을 쓰지 않는다(ADR 0002).
- (Windows) 긴 경로 폴더를 지울 때는 절대 경로를 그대로: cmd /c rmdir /s /q "\\?\<절대 경로>" — 변수 금지.
- 코드·스크립트 파일은 Write 도구로 만든다 — Bash heredoc은 따옴표·백슬래시를 바꿔 문법 오류를 낸다.
- 파이썬 스크립트는 처음부터 `sys.stdout.reconfigure(encoding="utf-8")`, 파일은 `encoding="utf-8", newline=""` — Windows 기본(cp949·CRLF)에 걸린다.
- 셸로 부르는 실행 파일(node·npm 등)은 전체 경로로, PATH가 다른 셸에서도 같은 것이 돌게.
- 변형·실험은 "어느 단언이 실패했나"로 판정한다(종료 코드만 보지 않는다). 흔들리는 테스트는 다시 돌리기 전에 원인부터.
- 백그라운드 반복(e2e 여러 번 등)은 도중에 멈추지 않는다 — 끝까지 기다리거나, 반복문이 멈춤 파일(예: `stop.flag`가 있으면 빠져나감)을 보게 만든다. 멈췄으면 프로세스 목록에서 명령줄로 남은 것을 찾아 PID로 끈다 — 백그라운드 작업 멈추기가 반복문을 못 끌 때가 있다.
- 비밀값(.env)을 읽거나 커밋하지 않는다.
- (자율 모드일 때만) 사용자에게 묻지 않는다. 권한: <spec 경로> "## 자율 모드 권한". 답이 없는 결정은 spec "열린 질문 / 가정"에
  `가정 n`으로 쓰고 진행, 막힌 곳은 <실험 기록 경로> 표에 한 줄. 권한 밖이 필요하면 하지 말고 보고의 "승인 대기"에 적는다.

## 끝내기
push → gh pr create (제목 `타입: 내용`, 한국어 본문 한 것/확인한 것/확인하지 않은 것, 마지막 줄 Closes #<이슈>, 서명 없음)
→ gh pr checks --watch 로 CI 통과까지. 머지하지 않는다.

## 보고 (한국어, 짧게)
PR 주소 / CI 결과 / 만든 것 / 테스트(개수·결과) / 변형 검사 결과 / 확인하지 않은 것 / 내가 정해야 할 것 / 위험
(자율 모드) 새로 한 가정 / 승인 대기(무엇·왜 권한 밖) / 이 PR이 권한 밖 경로를 건드렸나
```

## 보고를 받은 뒤 (사용자에게 말하기 전에 직접 확인)
- 보고만 믿지 않는다:
  ```bash
  gh pr checks <번호>
  gh pr view <번호> --json title,body,commits -q '.title, .body, (.commits[].messageHeadline)'
  git -C <워크트리> log origin/main..HEAD --format=%B     # 본문·트레일러가 없어야 한다
  git -C <워크트리> diff --stat origin/main...HEAD       # 금지 파일을 건드리지 않았나
  ```
- 서명·트레일러가 있거나 금지 파일을 고쳤으면 에이전트에게 고치게 하고(이어서 지시), 다시 확인한다. 검사 명령은 `intaeng:wrap-up` 5번과 같다.
- 사용자에게는 PR·CI·한 것·확인하지 않은 것·정할 것만 전한다. 머지는 사용자가 정한다 — 여러 개면 `intaeng:merge-train`.
- **자율 모드**(ADR 0016)면 사용자에게 전하지 않고, 위 확인이 통과하면 권한 묶음대로 `intaeng:merge-train`으로 머지한다. 보고의 "승인 대기"는 now.md `## 승인 대기`로 옮기고 다음 단계를 맡긴다. 사용자에게는 끝에 아침 보고로 한 번.
