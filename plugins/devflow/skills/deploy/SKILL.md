# 배포 (devflow)

운영 서버를 바꾸는 일이라 **실행 전에 사용자에게 무엇을 배포하는지 한 줄로 알리고**(커밋, 대상 서버, 재시작 시간 예상) 진행한다.
사용자가 이번 대화에서 배포를 요청했으면 그 요청이 승인이다. 요청 없이 배포하지 않는다.

## 순서
1. 배포할 코드가 원격 기본 브랜치와 같은지 확인한다(머지 후 `git fetch` → 배포용 작업 폴더를 그 커밋으로).
2. 미리보기: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/deploy.sh" --dry-run`
3. 실행: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/deploy.sh"` (이미 빌드했으면 `--skip-build`)
   - 사전 확인(`preCheck`, 예: 진행 중인 작업 0건)이 실패하면 멈춘다 — 사용자에게 알리고 기다린다.
   - 해시가 다르거나 UP이 안 되면 멈추고, 출력된 되돌리기 명령을 사용자에게 보여 준다(마음대로 되돌리지 않는다).
4. 결과를 사용자에게(단계별 시간이 기록에 남는다 — `report.sh`로 누적 요약): 커밋, 해시 일치, UP까지 걸린 초, 확인 항목 결과, 백업 파일 이름.
5. 프로젝트 기록(메모리·배포 기록 문서)에 같은 내용을 한 줄로 남긴다.

## 설정
`~/.config/devflow/<레포 이름>.json`의 `deploy` — 서버 주소·키 경로는 공개 레포에 올리지 않도록 레포 밖에 둔다.
예시는 `examples/config.example.json`.
