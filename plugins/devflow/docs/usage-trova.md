### 실사용에서 찾은 플러그인 버그 3개
1. 배포 후 확인이 "0건" 결과(`grep -c` 종료 코드 1)에서 스크립트 전체가 멈춤 → `|| true`, 확인 명령 입력 분리(0.1.1)
2. 앱 폴더로 cd한 뒤 설정을 다시 찾아 다른 레포 설정을 읽음 → 처음 찾은 설정 고정(0.1.2)
3. 원복 메시지에 남은 패치 수가 두 번 찍힘 → 출력 정리(0.1.3)

손으로 하던 절차를 그대로 옮겨도, 실제로 한 번 돌려 봐야 드러나는 문제가 있었다 — 그래서 첫 사용 기록을 남긴다.

## 수동 배포 시간 기준 (실측, 비교용)
같은 세션 기록에서 손으로 한 운영 배포 16번을 다시 쟀다(빌드 시작 → 마지막 보안 확인 응답, 도구 호출 시각 기준).
중앙값 **124초**, 평균 256초, 최소 95초, 최대 968초 — 긴 것은 권한 확인 대기·재시도가 끼었을 때다.
devflow 첫 배포는 98초(1회). 한 번의 시간 차이는 크지 않다 — 줄어드는 것은 **손으로 치는 단계(9단계 → 명령 1줄)와 빠뜨릴 여지**다.
0.2.0부터 배포는 단계별 시간(build·precheck·transfer·swap·up·checks)을, QA는 start→stop 시간과 탭 수를 기록하고 `report.sh`로 요약한다.

## 0.2.0 추가
- `local-server`: 로컬 서버 재시작 — 첫 실행 빌드 3초·기동 4초(로컬)
- `record-draft`: 작업 기록 초안에 테스트 수·최근 배포/QA 시간을 자동으로 채움
- `report`: 배포·QA 기록 요약

## 0.3.0 — 어떤 서비스에서도
- QA 환경(qa-sim)은 [qaflow](https://github.com/taehyeooo/qaflow)로 옮겨 테스트 데이터 정리·시나리오·API 확인과 한곳에 모음
- 배포의 서버 쪽 명령(교체·재시작·되돌리기)과 로컬 서버 실행 명령을 설정으로 — 기본값은 이전과 같은 명령(Trova 배포 동작 그대로)
