# 개선 추천 (benchflow)

## 순서
1. 판정 결과를 읽는다: `<레포>/<resultsDir>/_check-latest.json`(기본 `docs/bench/`). 없거나 오래됐으면 사용자에게 알리고 `bench.sh check [--tag]`를 먼저 돌릴지 묻는다.
2. 대상 고르기:
   - `나빠짐` — 전부
   - `변화 없음`·`좋아짐`이라도 같은 단위의 다른 지표보다 3배 이상 나쁘거나, 사용자가 이름을 지정한 지표
   - `비교 불가`는 대상이 아니다(먼저 baseline·환경을 맞추라고 안내)
3. 대상마다 `bench-advisor` 에이전트를 부른다(여럿이면 동시에). 넘길 것: 결과 JSON의 그 지표 항목 전체, 설정의 `cmd`·`entry`(설정 `~/.config/benchflow/<레포>.json`), 레포 경로.
4. 돌아온 추천을 그대로 붙이지 말고 한 번 검증한다: 인용한 `경로:줄`을 직접 열어 그 내용이 맞는지, 예상 효과에 "추정"이 붙었는지, 레포 CLAUDE.md·ADR과 부딪히지 않는지. 틀린 추천은 뺀다.
5. `<resultsDir>/advice/<지표>-<YYYYMMDD>.md`에 남긴다(판정 수치·추천·읽은 파일). 결과 파일은 레포에 커밋할 대상이다.
6. 새 추천이 하나 이상이면 알림: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/bench.sh" notify "benchflow: 추천 N건" "<지표들>"`.
7. 사용자에게 요약(지표·판정·추천 제목·예상 효과(추정))을 보여주고 **어떤 추천을 적용할지 묻는다**. 자동으로 고치지 않는다.
8. 사용자가 고른 추천을 적용했다면, 같은 지표를 `bench.sh run <지표> --label after-<짧은 설명>` 또는 `check`로 다시 재서 advice 파일 끝에 "적용 → 전/후 수치"를 덧붙인다.

## 지킬 것
- 추천의 모든 코드 언급은 실제로 연 파일·줄이어야 한다. 열지 않은 코드에 대한 추측은 쓰지 않는다.
- 예상 효과는 언제나 "추정", 실측은 benchflow 기록으로만.
- 레포 CLAUDE.md의 비용 원칙(예: 유료 API 금지)을 따른다.
