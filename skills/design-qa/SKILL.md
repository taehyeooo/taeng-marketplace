# 디자인 QA (uiflow)

## 순서
1. 대상 화면과 상태를 정한다: 비어 있음 · 하나 · 여러 개 · 긴 제목 · 진행 중 · 오류. 데이터가 필요하면 테스트 계정에만 만들고, 끝나면 지운다.
2. 상태마다 `design-sweep`으로 글자 크기별 한 장을 만든다(다크 모드를 지원하면 `--dark`).
3. 체크리스트로 본다.

| 항목 | 기준 |
|---|---|
| 잘림 | 숫자·핵심 단어가 … 로 사라지지 않음(중요한 정보는 앞에) |
| 위계 | 누를 수 있는 것과 안내만 하는 것이 구분됨(같은 배경·같은 모양 반복 금지) |
| 정렬 | 같은 줄의 아이콘·글자 시작 위치가 맞음 |
| 큰 글자 | 접근성 최대에서도 버튼·아이콘이 그려지고 화면 밖으로 안 밀림 |
| 터치 | 누르는 곳 44pt 이상(작으면 hitSlop) |
| 상태 | 빈 상태·로딩·오류가 각각 있고, 로딩 중에 빈 상태가 깜빡이지 않음 |
| 문구 | 사용자에게 안 보이는 원문(해시태그·내부 오류 문장)이 그대로 나오지 않음 |

4. 결과를 표로: `# · 무엇이 · 어디서(화면·상태·글자 크기) · 이번 기능 / 원래 있던 문제 · 제안`. 사용자가 고칠 범위를 고르게 한다.
5. 고친 뒤 `design-compare`로 전·후 이미지를 만들고, 다시 `design-sweep`으로 확인한다.
6. 수정 후 자동 검사 훅(타입·디자인 토큰)이 실패를 알리면 그 자리에서 고친다.
